Recourse: car-insurance rehearsal

Outcome to demonstrate
Prepare a source-linked case brief; call a consenting participant acting as an
AAA representative; show the actual returned transcript and document request;
attach the labeled sample photos and estimate; review the updated packet.
Keep the sample packet in Recourse. Show AAA's public site separately, read-only.
The result is a prepared packet, not a submitted or approved insurance claim.

Before recording
1. Configure .env.local from .env.example with funded OpenAI and Dial credentials.
   For dev:live, Dial settings may live in ~/.config/speedhacks/dial.env.
   Set REFUND_MODE=live, BROWSER_ENABLED=true and BROWSER_HEADLESS=false.
   Install Chromium with npx playwright install chromium. Run npm run dev:live.
   Open http://127.0.0.1:3000/ without ?api=fixture.
2. Have docs/demo/samples/auto-insurance-intake.txt ready to paste and these two
   files ready in the file chooser: auto-damage-sample.png and
   auto-repair-estimate.txt. Both are clearly labeled synthetic examples.
3. Have a willing participant ready on speakerphone. Confirm their number in
   the app yourself. Do not choose a number from the insurer directory for this
   role-play. Agree that they will request photos and an estimate, not claim
   that a real loss, policy, claim approval or payment exists.
4. Preserve your current browser session. Cases belong to an owner cookie in
   local SQLite; another browser, teammate or cleared cookie may not see them.
   Git does not share cases, credentials, phone numbers or signed-in sessions.

Recording sequence (you operate the website)
1. Start a new car-insurance case. Paste auto-insurance-intake.txt and Send once.
   Wait for analysis to complete. Review the facts and preparation document.
   An unknown policy number or repair amount is not a reason to invent one.
2. Under Review insurer information call, choose Review call. Enter the participant's
   number, select 60–120 seconds, and confirm the recipient. Authorize call,
   review the frozen brief, then Place live call. Only that final button calls.
3. The participant asks: "What vehicle and damage?" and "When and where?"
   Then says: "Please provide damage photos and a repair estimate so we can
   review the next steps." End the call normally. Speakerphone supplies live
   audience audio; the website recording, if available, is for after the call.
4. Keep the case open. Wait for Call results, the transcript and the recipient's
   quoted document request. A completed call may initially say transcript
   pending. Refresh checks the existing attempt; it does not place another call.
5. Choose Add requested documents in the latest call result, attach both sample
   files using Evidence, then Upload evidence. Wait for the
   real analysis to finish. Show the updated brief's evidence index and download
   the updated preparation document. No second call is needed or automatic.
6. Open the AAA public-site action separately if desired. The side browser can
   show the actual public page. With this sample case, keep it read-only: do not
   log in, enter policy details, fill claim fields, upload files or submit.
   Finish by showing the packet in Recourse, ready for the user's review.

Fast recovery
- Analysis still processing: wait; do not create a second case or resubmit.
- Analysis failed: saved answers/evidence remain; use the explicit retry control.
- Conflicting fact: enter the correct clarification, then review the updated
  brief before external actions. Do not bypass an actual conflict for the video.
- Call connecting/uncertain: keep the existing attempt and refresh its status.
  Do not authorize another call until the first attempt is resolved.
- Transcript pending: wait for a later poll; do not claim a returned document
  request until the actual recipient's words are visible.
- AAA site unavailable, regional routing, login or CAPTCHA: show the saved
  packet and stop the public-site portion. Never substitute a fake live page.

Acceptance before saying the rehearsal passed
[ ] Insurance analysis completes with no unresolved contradictions.
[ ] Prepared brief includes vehicle, incident date/location and observed damage.
[ ] Authorization identifies the reviewed participant, purpose and time limit.
[ ] Exactly one live call is dispatched after the user's Place live call action.
[ ] Actual call results and transcript appear in this same case.
[ ] Recipient's document request is visibly attributed to the recipient.
[ ] Both evidence files appear once; updated brief survives reopening the case.
[ ] Claim/payment outcome remains unknown/unverified; nothing is submitted.
[ ] AAA public page is shown separately; no sample data reaches its forms.

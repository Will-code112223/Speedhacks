MODES AND ENVIRONMENT (.env.example)
- REFUND_MODE=simulated (default): no credentials; case.mode === "simulated"; heuristic extraction; T2's simulated
  voice adapter. Scenario by destination suffix: …0001 rejected before dispatch, …0002 dispatch_unknown,
  …0003 completed/denied, …0004 completed/needs information, …0005 failed, …0006 cancelled, else completed/approved
  with a reference number. Timings: SIMULATED_QUEUED_MS (2000), SIMULATED_IN_PROGRESS_MS (6000).
- REFUND_MODE=live: requires LLM_MODEL + OPENAI_API_KEY (POST /api/cases is 503 otherwise) and DIAL_API_KEY,
  DIAL_FROM_NUMBER, DIAL_WEBHOOK_SECRET (POST …/calls and the webhook are 503 otherwise). No silent fallback.
  Live extraction failure creates the case with no extracted facts and an extraction_failed timeline entry.
- Reconciliation: RECONCILE_MIN_INTERVAL_MS (2000), TRANSCRIPT_WAIT_MS (45000).
- DATA_DIR (./data): refund.sqlite + uploads/. Local disk only; not for ephemeral/serverless hosts.

KNOWN LIMITS / PROPOSED CONTRACT NOTES (not applied; coordinate before changing V1)
- One attempt per authorization is enforced literally: a definitive pre-dispatch refusal (e.g. provider rate limit)
  consumes the authorization; the user must edit a fact and re-authorize. Proposed V1.1: allow a new attempt when
  the previous one is a pre-dispatch refusal with no provider id. (Alike decision recorded.)
- dispatch_unknown with no provider id has no automatic correlation; manual verification in the provider dashboard
  is required before any new attempt (nextAction says so). No automatic redial exists anywhere.
- Transcript reconciliation is driven by GET polling (bounded), not a worker; if nobody polls, it resumes on the next GET.
- Simulated mode is explicit in data (mode) and must be labeled in the UI.
- npm 11 install-script gating: package.json allowScripts approves better-sqlite3 and esbuild.

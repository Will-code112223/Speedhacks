EXACT INTEGRATION EXAMPLE (T2)
  import {createDialAdapter, DialAdapterError} from "@/integrations/dial";
  const voice = createDialAdapter({mode: "live"}); // choose mode explicitly
  const result = await voice.startCall({
    attemptId: storedAttempt.id,
    caseId: authorizedCase.id,
    authorizationId: authorizedCase.authorization.id,
    to: frozenAuthorization.supportPhone,
    brief: frozenAuthorization.approvedBrief,
  });
T2 persists/locks one attempt per authorization before this invocation. Return
the old attempt for repeated authorizationId/requestId. The adapter does not
persist or verify customer authorization itself; never pass raw client facts.
Capture accepted.providerCallId durably. On rejected, the documented request
was refused before dispatch. On dispatch_unknown, preserve the attempt and
block new dispatch/authorization. Do not turn uncertainty into a retry-safe503.

The exact API is POST https://api.getdial.ai/api/v1/calls with Bearer auth,
Idempotency-Key: attemptId, and {to,fromNumber,outboundInstruction,language,
maxCallDurationSeconds}. Exactly one POST is sent per invocation. Current
OpenAPI/SDK support the key, although older voice-call prose says otherwise.
Successful 2xx requires a valid call.id. 409 idempotency_conflict, ambiguous409,
5xx, transport/timeout errors, malformed success and unusable IDs remain unknown.
Known HTTP400/401/402/403/404/429 and 409 calling_disabled are sanitized refusals.
No fabricated correlation lookup. A provider ID is never guessed after loss.

GET /api/v1/calls/{id} returns {call}. Queued/Ringing -> queued;
In-Progress -> in_progress; Terminated/completed -> completed;
Terminated/canceled -> cancelled; busy/no-answer/failed -> failed.
Unknown states throw INVALID_PROVIDER_RESPONSE. Cancellation flags alone do
not imply cancelled: an answered call can end completed after a manual stop.
Transcript/duration null remains null; transcriptTurns is a speaker-labelled
fallback. No snapshot infers a refund decision or confirmed payment.
Reads default to one retry on transport/5xx failures (max2 configurable);
each request including JSON body has a 10s deadline (max60s configurable).

WEBHOOK ROUTE (T2 OWNS)
Use Node runtime and obtain bytes BEFORE JSON parsing:
  const raw = new Uint8Array(await request.arrayBuffer());
  const event = await voice.verifyWebhook(raw, request.headers);
Limit incoming HTTP body size to 1MiB before buffering; adapter also checks size.
INVALID_WEBHOOK ->401; MISSING_CONFIG is server misconfiguration, not a forged
request. Authenticated irrelevant event ->null, safe204. Relevant event returns
{eventId,providerCallId,type:"call.ended"} only after signature/envelope/data checks.
Durably accept/deduplicate before204; keep unknown call IDs queued so an event
arriving before dispatch's response can reconcile. Bind the matched provider ID
to an owned attempt; never trust a webhook's phone number as case ownership.
Do not reject legitimate duplicates in memory: they pass verification each time.

Authentication: X-Dial-Signature t=<unix-seconds>,v1=<64hex>, HMAC-SHA256 of
UTF8(timestamp + ".") followed by the EXACT raw bytes, keyed by the entire
subscription secret. Absolute skew >=300s is rejected. X-Dial-Event-ID and
X-Dial-Event-Type must match signed id/type. Expected object:event/version:1,
createdAt timestamp, matching call relatedObject and all documented ended data
fields. Unknown fields are tolerated. Malformed authenticated payloads reject.
Configure a public HTTPS subscription for call.ended only after T2 provides
the running authenticated route. Nothing has been deployed or subscribed here.

CRITICAL: LATE TRANSCRIPT RECONCILIATION
call.ended has NO transcript and transcriptAvailable can be false. Dial emits
call.transcribed later. V1 only normalizes call.ended, so call.transcribed returns
null. T2 MUST persist a reconciliation job: fetch getCall after ended, retry
bounded reads until transcript arrives, then atomically publish terminal CallV1
plus evaluated outcome/timeline. Proposed job delays 0/2/5/10/20 seconds; if still
missing, publish an explicit unknown outcome and a manual-review next step.
Do not publish terminal state early and depend on UI polling to get the transcript.
T2 may deliberately coordinate V2 call.transcribed support later; not changed here.

The deterministic sim_dial_<hash> is derived from the captured input. getCall
returns an immediate completed synthetic needs-information transcript with a

are rejected. This fixture is independent of T2's early simulated-voice adapter.

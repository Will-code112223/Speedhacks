WEBHOOK ROUTE (T2 OWNS)
src/app/api/webhooks/dial/route.ts uses Node runtime and collects exact bytes
BEFORE JSON parsing. Its bounded stream reader cancels requests over 1 MiB,
including absent/false Content-Length, before verification and full buffering.
Oversized requests return 413; the adapter independently checks raw byte size.
INVALID_WEBHOOK -> 401; MISSING_CONFIG is server misconfiguration, not a forged
request. Authenticated irrelevant event -> null, safe 204. Relevant event returns
{eventId,providerCallId,type:"call.ended"} only after signature/envelope/data checks.
Durably accept/deduplicate before 204; keep unknown call IDs queued so an event
arriving before dispatch's response can reconcile. Bind the matched provider ID
to an owned attempt; never trust a webhook's phone number as case ownership.
Do not reject legitimate duplicates in memory: they pass verification each time.

Authentication: X-Dial-Signature t=<unix-seconds>,v1=<64hex>, HMAC-SHA256 of
UTF8(timestamp + ".") followed by the EXACT raw bytes, keyed by the entire
subscription secret. Absolute skew >=300 s is rejected. X-Dial-Event-ID and
X-Dial-Event-Type must match signed id/type. Expected object:event/version:1,
createdAt timestamp, matching call relatedObject and all documented ended data
fields. Unknown fields are tolerated. Malformed authenticated payloads reject.
Configure a public HTTPS subscription for call.ended only after T2 provides
the running authenticated route. Nothing has been deployed or subscribed here.

The following route factory is a reference example, not the integrated route's
actual export. Supply T2's durable acceptance callback; its Promise must resolve
only AFTER a transaction commits the event/job or recognizes a stored duplicate.
It must persist unmatched provider IDs for reconciliation, never silently drop
them. Route body reading is bounded even if Content-Length is absent or false.

  import {createDialAdapter, DialAdapterError} from "@/integrations/dial";
  import type {VerifiedVoiceEvent} from "@/contracts/voice";

  export function makeDialWebhookPOST(
    acceptDurably: (event: VerifiedVoiceEvent) => Promise<void>,
  ) {
    const voice = createDialAdapter({mode: "live"});
    return async function POST(request: Request): Promise<Response> {
      const reader = request.body?.getReader();
      if (!reader) return new Response(null, {status: 400});
      const chunks: Uint8Array[] = [];
      let length = 0;
      try {
        while (true) {
          const {done, value} = await reader.read();
          if (done) break;
          length += value.byteLength;
          if (length > 1_048_576) {
            await reader.cancel();
            return new Response(null, {status: 413});
          }
          chunks.push(value);
        }
      } catch {
        return new Response(null, {status: 400});
      } finally {
        reader.releaseLock();
      }
      const raw = new Uint8Array(length);
      let offset = 0;
      for (const chunk of chunks) { raw.set(chunk, offset); offset += chunk.length; }
      try {
        const event = await voice.verifyWebhook(raw, request.headers);
        if (event) await acceptDurably(event);
        return new Response(null, {status: 204});
      } catch (error) {
        return new Response(null, {status:
          error instanceof DialAdapterError && error.code === "INVALID_WEBHOOK"
            ? 401 : 503});
      }
    };
  }

The integrated route exports runtime="nodejs" and calls the case service's
handleWebhook after its bounded read. A future implementation using the factory
above would supply POST=makeDialWebhookPOST(acceptDialEventDurably). That callback
needs a unique eventId and durable reconciliation state;
use a transaction/upsert to make concurrent duplicate delivery safe. Configure
request-header/body timeouts at the HTTP host. Do not background work in an
unawaited Promise after returning 204; serverless hosts may stop execution.

CRITICAL: LATE TRANSCRIPT RECONCILIATION
call.ended has NO transcript and transcriptAvailable can be false. Dial emits
call.transcribed later. V1 only normalizes call.ended, so call.transcribed returns
null. The integrated backend persists reconciliation timestamps and drives reads
through GET /api/cases/:id; there is no background worker. During the default 45 s
TRANSCRIPT_WAIT_MS, a completed provider call without text remains nonterminal
in the case. Text arrival publishes terminal state/outcome/timeline atomically.
Expiry publishes completed with an explicit unknown outcome and next action.
Later case GETs can retrieve a missing transcript without redialing: default
LATE_TRANSCRIPT_INTERVAL_MS=30000, within LATE_TRANSCRIPT_WINDOW_MS=86400000
(24 h measured from attempt creation). If no GET occurs, no work advances. Past
that window, manual provider review is required. Reopening a case is a read,
not authorization for another call.
Late text belongs to its original call. After awaiting the provider, the backend
rechecks authorization ID and case revision inside the publication transaction.
It can attach old text to its original call, but only the current matching
authorization/revision may change the case outcome. Material edits reset the
previous outcome; completed calls from older authorizations cannot determine the
new revision's status. Null, empty and whitespace-only transcripts are consistently
treated as missing. Repeated GETs do not publish the same outcome twice, and the
completed call state never regresses. Six new regressions verify these rules.
T2 may deliberately coordinate V2 call.transcribed support later; not changed here.

PROPOSED WORKER ALTERNATIVE — NOT IMPLEMENTED IN THIS INTEGRATION
The following earlier example remains a design option if GET-driven operation
is replaced. It is not evidence of a background queue. Each proposed job is
leased from a durable queue. The callbacks below
must compare the lease/attempt/version in a transaction, so stale workers cannot
overwrite a newer outcome. The retry number is stored durably, not a JS timer.
Each callback commits job state before resolving; a thrown error leaves the job
retryable by the queue. This code schedules read-only retries and never calls
startCall. Separate queue delivery retry from the bounded provider-read budget.

  import type {VoiceAdapter, VoiceSnapshot} from "@/contracts/voice";

  type Job = {id: string; providerCallId: string; readIndex: number; lease: string};
  interface Jobs {
    reschedule(job: Job, nextReadIndex: number, dueAt: number): Promise<void>;
    publishWithOutcome(job: Job, snapshot: VoiceSnapshot): Promise<void>;
    manualReview(job: Job, snapshot: VoiceSnapshot | null): Promise<void>;
  }
  export async function reconcileEndedCall(
    job: Job, jobs: Jobs, voice: VoiceAdapter, now: () => number = Date.now,
  ): Promise<void> {
    // First read immediately; subsequent durable delays are 2, 5, 10, 20 seconds.
    const delays = [2_000, 5_000, 10_000, 20_000] as const;
    let snapshot: VoiceSnapshot | null = null;
    try { snapshot = await voice.getCall(job.providerCallId); }
    catch { /* Preserve unknown state; retry only the read. */ }
    const terminal = snapshot && ["completed", "failed", "cancelled"].includes(snapshot.state);
    if (terminal && snapshot?.transcript?.trim()) {
      await jobs.publishWithOutcome(job, snapshot);
      return;
    }
    const delay = delays[job.readIndex];
    if (delay !== undefined) {
      await jobs.reschedule(job, job.readIndex + 1, now() + delay);
      return;
    }
    await jobs.manualReview(job, snapshot);
  }

publishWithOutcome stores terminal CallV1, evaluated outcome and timeline in the
SAME transaction that completes the job. manualReview publishes an explicit
unknown case outcome/next action and retains an honest provider state; it does
not invent completed status when all reads failed or remained nonterminal.
If no terminal provider state was verified, keep the attempt blocked and expose
manual reconciliation. A late transcript after the bounded window requires an
explicit read-only reconciliation path; never redial to obtain a transcript.
The evaluator treats transcript text as evidence, not instructions. A spoken
approval still leaves paymentStatus="unverified" absent separate payment proof.
